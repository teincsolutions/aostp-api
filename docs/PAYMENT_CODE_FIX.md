# Payment Creation Failure — Issue & Resolution

**Date:** February 9, 2026
**Severity:** High
**Status:** Resolved

---

## The Problem

Payment creation was intermittently failing with a duplicate code error when multiple staff members processed payments around the same time. The system rejected the second payment entirely, requiring the user to retry manually.

This occurred because the payment reference code (e.g. `RCPT-20260209-0006`) was generated by counting how many payments existed that day and adding one. When two payments were submitted simultaneously, both counted the same number and attempted to use the same code — causing one to fail.

## Business Impact

- Staff experienced unexpected errors during payment processing
- Customers faced delays while staff retried failed transactions
- Mobile money and card payments were particularly vulnerable due to the additional processing time with external payment providers

## The Fix

Payment codes are now generated using a combination of the current timestamp (down to the millisecond) and a short random identifier — for example, `RCPT-20260209-142740300-A3F9`. This eliminates the need to check the database before creating a code, making collisions virtually impossible even under heavy concurrent use.

As a safety net, the system will automatically retry with a new code in the extremely unlikely event of a duplicate.

The same improvement was applied to all other auto-generated codes in the system (customer IDs, invoice numbers, tracking codes, delivery IDs).

## Additional Improvement

Raw database errors are no longer shown to users. All technical error messages are now replaced with clear, user-friendly responses while the full details remain available in system logs for the technical team.
